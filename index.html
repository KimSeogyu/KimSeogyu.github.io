blockchain

  • Aptos와 Move: Aptos는 합의로 순서를 정하고 Move VM으로 상태를 바꾸는 체인이며, Move는 자산 소유권과 조작 권한을 언어가 강제한다.
  • Non-Custodial 지갑 설계: Non-custodial 지갑은 서버를 없애는 설계가 아니라, 서버가 많이 알되 승인은 만들 수 없도록 지갑 승인·복구·자동 실행을 서로 다른 권한으로 나누는 설계다.
  • 데이터 가용성: 데이터 가용성은 해시가 맞는지가 아니라 데이터를 실제로 받을 수 있는지의 문제이며, Celestia는 2D 이레이저 코딩과 무작위 샘플링으로 이를 확률적으로 확인한다.
  • 블록체인 기초: 블록체인은 합의, 데이터 구조, 암호학으로 유지되는 불변 로그이며, 핵심은 탈중앙 자체가 아니라 검증 비용을 어떻게 나누느냐다.
  • 블록체인 인덱서: 블록체인 인덱서는 체인 이벤트를 수집하고 파싱해 조회하기 좋은 DB에 적재하는 오프체인 읽기 최적화 계층이다.
  • 비트코인 스크립트와 Ordinals: 비트코인은 단순한 스택 스크립트로 UTXO 소비 조건만 검증하고, Ordinals와 BRC-20은 그 위에 인덱서의 해석에 기대는 자산 실험을 얹었다.
  • 온체인 거래 실행과 오라클: 온체인 금융의 핵심은 결과를 기록하는 것이 아니라 상태 전이를 어떤 합의와 가격 입력 아래 실행하고, 언제 멈출지 정하는 것이다.
  • 지갑 키 관리와 다자 서명: 키는 시드 하나에서 계층적으로 파생해 복구를 단순하게 하고, 여러 참여자가 서명해야 하면 검증식과 요구 정족수에 맞춰 FROST, MuSig2, Threshold ECDSA를 고른다.

distributed-systems

  • Ceph: Ceph는 CRUSH로 중앙 조회 없이 데이터 위치를 계산하는 분산 스토리지로, 이레이저 코딩 풀에서는 배치 규칙과 메타데이터 일관성이 내구성을 좌우한다.
  • MinIO: MinIO는 이레이저 코딩으로 객체를 여러 디스크에 나눠 저장하고, 여러 겹의 손상 감지와 힐링으로 데이터를 정상 상태로 되돌리는 객체 스토리지다.
  • 이레이저 코딩: 데이터를 k개 조각과 m개 패리티로 나눠 최대 m개 손실까지 복구하는 저장 방식으로, 복제보다 공간을 아끼는 대신 복구 비용을 더 낸다.

backend

  • Enterprise Go: 운영 가능한 Go 서비스를 만드는 구조, 서버, 동시성, DB, 외부 통신, 테스트, 관측성, 빌드 표준을 묶은 실무 기준이다.
  • GitLab CI/CD: GitLab CI/CD는 저장소의 .gitlab-ci.yml에 Stage와 Job을 정의하고 Runner가 실행하는 GitLab 내장 파이프라인이다.
  • GitOps: GitOps는 Git을 유일한 원본으로 두고 클러스터 안의 에이전트가 그 상태를 끌어와 계속 맞추는 배포 방식이다.
  • Go 실무 패턴: Go 서비스를 오래 유지하려면 에러는 값으로, 추상화는 소비자 쪽에, 의존성은 생성자에 드러내고, 성능은 측정한 뒤에만 손댄다.
  • gRPC와 Protobuf API 계약: Proto 정의 하나를 API 계약의 원본으로 두고, 호환성 검사와 코드 생성으로 gRPC와 HTTP/JSON을 함께 제공하는 방식이다.
  • Kubernetes: Kubernetes는 원하는 상태를 선언하면 컨트롤러가 현재 상태를 계속 그 상태로 맞추는 컨테이너 오케스트레이션 플랫폼이다.
  • Markdown 변환과 출판 파이프라인: 문서를 Markdown으로 바꾸거나 Markdown을 사이트로 내보낼 때는 원본과 산출물의 권위를 나누고, 의미를 담은 중간 표현과 최종 산출물 검증을 둔다.
  • 도메인 모델링과 상태 설계: 비즈니스 규칙이 깨지지 않도록 상태를 바꾸는 경로를 좁히는 설계로, 잘못된 연산은 검사하기보다 아예 표현할 수 없게 만든다.
  • 빌드와 릴리스 운영: 작은 변경을 자주 통합하고, 이미지와 설정을 매번 같은 방식으로 만들어 배포 결과를 예측 가능하게 하는 운영 규칙이다.
  • 연결 자원 고갈: 포트나 파일 디스크립터가 바닥나 연결이 실패하는 문제로, 커널 한도를 올리기 전에 애플리케이션의 연결 관리부터 고쳐야 재발하지 않는다.
  • 통합 테스트와 E2E 테스트: mock으로 잡히지 않는 장애를 배포 전에 찾기 위해 실제 의존성을 띄운 통합 테스트와 환경별로 계층을 나눈 E2E 테스트를 함께 둔다.
  • 트래픽 확장 설계: 병목이 옮겨 갈 때마다 필요한 만큼만 구조를 키우고, 순간 폭주는 쓰기 경합 제어로, 실시간 연결은 상태 일관성으로 다룬다.

ai-ml

  • LLM 지식베이스와 메모리: LLM이 오래 쓰는 지식베이스는 정교한 구조보다 싸게 기록하고 정확히 회수하는 것이 먼저이며, 실제로 막히는 지점은 검색보다 기록(컴파일) 단계였다.
  • 검색 랭킹과 하이브리드 검색: 키워드 랭킹(BM25)과 벡터 검색은 서로 다른 곳에서 실패하므로 함께 돌리고, 두 결과는 점수가 아니라 순위로 합친다.
  • 로컬 LLM과 에이전트 프레임워크: 로컬 LLM 장비는 목표 모델이 메모리에 안정적으로 올라가는지로 고르고, 에이전트 흐름은 호출 계층과 상태 제어 계층을 나눠 짠다.

database

  • MongoDB 샤딩과 스토리지 엔진: MongoDB 운영은 샤드 키 선택과 WiredTiger의 캐시·체크포인트·저널 정책 두 가지가 성패를 가른다.
  • PostgreSQL 인덱스와 쿼리 튜닝: 데이터의 모양에 맞는 인덱스를 고르고, 실행 계획과 통계를 근거로 작은 변경부터 적용하는 PostgreSQL 성능 관리 방법이다.
  • Redis 활용 패턴: Redis를 락, 이벤트 로그, 실시간 라우팅에 쓸 때는 정상 동작보다 실패했을 때의 동작을 먼저 설계한다.
  • 트랜잭션과 격리수준: ACID는 이론이 아니라 운영 계약이며, 트랜잭션 경계와 격리수준과 Upsert는 도메인이 견딜 수 있는 이상현상에 맞춰 고른다.

data-engineering

  • 시점 정합성: 과거의 결정을 재현하려면 그때 실제로 알 수 있었던 데이터만 써야 하며, 이를 위해 시각과 개정과 결측을 수집 단계에서 구분해 남긴다.

languages

  • 언어별 문법 메모: 언어 기능을 쓸 때 실수가 나는 지점은 문법보다 제어 흐름, 타입 안전성, 의도의 명확성이며, Python asyncio, Dart, TypeScript 데코레이터, 비트 연산에서 그 예를 모았다.

frontend

  • 웹 지도와 공간 연산: 웹 지도는 GeoJSON을 공통 형식으로 두고 렌더링, 클라이언트 연산, 저장과 무거운 연산을 각각 다른 도구에 맡기며, 품질은 시각 효과보다 입력과 상태의 일관성에서 나온다.

quant

  • 퀀트 리서치: 퀀트 리서치는 통계적으로 검증 가능한 전략을 시장 레짐에 맞춰 찾는 일이며, 백테스트는 시행 횟수와 비용과 시점 정합성을 지켜야 믿을 수 있다.

misc

  • 키보드 선택: 하루 대부분을 타이핑하는 작업 환경에서 키보드는 타건감, 정숙함, 편안함을 한꺼번에 만족하는지로 고른다.
