단일 .gitlab-ci.yml이 수백 줄로 커지면 관리가 어려워집니다.

패턴용도

include 유형

실전 구조

project/
├── .gitlab-ci.yml              # 메인 파일
├── .gitlab/
│   ├── ci/
│   │   ├── build.yml           # 빌드 Jobs
│   │   ├── test.yml            # 테스트 Jobs
│   │   └── deploy.yml          # 배포 Jobs
│   └── templates/
│       └── docker.yml          # 공통 템플릿

Parent-Child Pipelines

Parent Pipeline이 Child Pipeline을 트리거하는 구조입니다.

기본 구조

flowchart TB
    subgraph Parent [Parent Pipeline]
        P1[build]
        P2[trigger-child]
    end
    
    subgraph Child [Child Pipeline]
        C1[test-unit]
        C2[test-e2e]
        C3[deploy]
    end
    
    P1 --> P2
    P2 -->|trigger| C1 & C2
    C1 & C2 --> C3

정적 Child Pipeline

strategy 옵션

옵션동작
dependChild 완료까지 Parent Job 대기
(없음)Parent Job 즉시 완료, Child 비동기 실행

런타임에 Child Pipeline YAML을 생성합니다.

동적 생성 예제

Monorepo 패턴

변경된 파일 기반 트리거

rules:changes를 사용하여 특정 파일 변경 시에만 Child를 트리거합니다.

flowchart TB
    subgraph Parent [Parent Pipeline]
        Check[변경 감지]
    end
    
    subgraph Children [Child Pipelines]
        F[Frontend Pipeline]
        B[Backend Pipeline]
        S[Shared Pipeline]
    end
    
    Check -->|frontend/* 변경| F
    Check -->|backend/* 변경| B
    Check -->|shared/* 변경| S

Multi-Project Pipelines

다른 프로젝트의 파이프라인을 트리거합니다.

기본 사용법

변수 전달

양방향 트리거 (Upstream → Downstream)

flowchart LR
    subgraph Upstream [Project A - 라이브러리]
        U1[build]
        U2[publish]
        U3[trigger]
    end
    
    subgraph Downstream [Project B - 앱]
        D1[install]
        D2[build]
        D3[deploy]
    end
    
    U1 --> U2 --> U3
    U3 -->|trigger| D1
    D1 --> D2 --> D3

실전 예제: 마이크로서비스 배포

Pipeline 간 아티팩트 공유

Parent → Child

Multi-Project 간 아티팩트

파이프라인 시각화

Pipeline Graph

flowchart TB
    subgraph MainPipeline [Main Pipeline]
        direction LR
        Build[Build Stage]
        Test[Test Stage]
        Deploy[Deploy Stage]
    end
    
    subgraph ChildPipelines [Child Pipelines]
        direction TB
        Frontend[Frontend Pipeline]
        Backend[Backend Pipeline]
    end
    
    Build --> Frontend & Backend
    Frontend & Backend --> Deploy

GitLab UI에서는 이러한 관계가 시각적으로 표시됩니다.

정리

패턴용도키워드
include설정 파일 분리include: local/project/remote
Parent-Child동적 파이프라인trigger: include:
Multi-Project프로젝트 간 트리거trigger: project:
동적 생성런타임 파이프라인artifact: + trigger
