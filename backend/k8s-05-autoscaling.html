오토스케일링의 3가지 축

Kubernetes 오토스케일링은 무엇을 스케일링하느냐에 따라 세 가지로 구분됩니다.

수평 (Horizontal)Pod 개수HPA, KEDA
수직 (Vertical)Pod 리소스 (CPU/Memory)VPA
클러스터Node 개수Cluster Autoscaler, Karpenter

HPA (HorizontalPodAutoscaler)

HPA v2: 현재 Stable API

IMPORTANT

HPA는 현재 autoscaling/v2가 stable입니다. v2beta2는 deprecated되었습니다.

기본 설정: CPU 기반

다중 메트릭: CPU + Memory

NOTE

다중 메트릭 사용 시 HPA는 가장 큰 replica 수를 요구하는 메트릭을 기준으로 스케일링합니다.

메트릭 타입 완전 정리

flowchart LR
    subgraph Metrics ["HPA 메트릭 타입"]
        R["Resource\n(CPU, Memory)"]
        P["Pods\n(커스텀 Pod 메트릭)"]
        O["Object\n(다른 K8s 오브젝트)"]
        E["External\n(외부 시스템)"]
    end
    
    R --> MS["Metrics Server"]
    P --> PA["Prometheus Adapter"]
    O --> PA
    E --> PA
타입설명예시
ResourceCPU, Memory (Metrics Server 필요)평균 CPU 70%
PodsPod당 커스텀 메트릭requests-per-second
Object다른 K8s 오브젝트의 메트릭Ingress의 requests-per-second
External외부 시스템 메트릭SQS 큐 메시지 수

External 메트릭 예시: AWS SQS

Scaling Behavior: 급격한 스케일링 방지

sequenceDiagram
    participant HPA as HPA Controller
    participant Metrics as Metrics Server
    participant Deploy as Deployment
    
    loop 매 15초
        HPA->>Metrics: 메트릭 조회
        Metrics-->>HPA: CPU 사용률 반환
        
        alt CPU > 70%
            HPA->>Deploy: Scale Up (behavior 정책 적용)
        else CPU < 70%
            Note over HPA: stabilizationWindow 대기
            HPA->>Deploy: Scale Down (10%씩)
        end
    end

VPA (VerticalPodAutoscaler)

VPA 설치 (별도 설치 필요)

CAUTION

VPA는 Kubernetes 기본 제공이 아닙니다. 별도 설치가 필요합니다.

VPA 4가지 모드

flowchart TB
    subgraph Modes ["VPA 모드"]
        Auto["Auto / Recreate\nPod 재생성으로 리소스 변경"]
        Initial["Initial\n생성 시에만 적용"]
        Off["Off\n추천만 제공"]
    end
    
    Auto --> |Pod 삭제 후 재생성| Pod1["새 Pod\n(큰 리소스)"]
    Initial --> |최초 생성 시| Pod2["Pod\n(추천 리소스)"]
    Off --> |변경 없음| Pod3["기존 Pod"]
모드동작사용 사례
AutoPod 재생성으로 리소스 변경일반적인 워크로드
RecreateAuto와 동일Auto의 별칭
Initial생성 시에만 적용StatefulSet, 중단 민감 워크로드
Off추천만 제공, 변경 없음모니터링 용도

In-place Pod Resizing (K8s 1.33+)

TIP

Kubernetes 1.33부터 In-place Pod Resizing이 beta로 기본 활성화됩니다. Pod를 재생성하지 않고 리소스를 변경할 수 있습니다. 단, 2024년 기준 VPA는 아직 In-place Resizing을 지원하지 않으며, 통합이 진행 중입니다.

HPA + VPA 동시 사용 시 주의

WARNING

HPA와 VPA를 **같은 메트릭(CPU/Memory)**으로 동시에 사용하면 충돌이 발생합니다. HPA가 Pod 수를 늘리면 VPA가 리소스를 줄이고, 다시 HPA가 Pod를 늘리는 악순환이 발생할 수 있습니다.

권장 패턴:

  • HPA: Custom/External 메트릭 (requests-per-second, 큐 길이)
  • VPA: CPU/Memory (Off 모드로 추천만 활용)

KEDA (Kubernetes Event-driven Autoscaling)

KEDA란?

KEDA는 HPA를 확장하여 이벤트 기반 스케일링을 제공합니다. 60개 이상의 트리거를 지원합니다.

트러블슈팅 가이드

HPA가 스케일링하지 않음

흔한 원인:

  1. Metrics Server 미설치
  2. Pod에 resource requests 미설정 (HPA 작동 불가)
  3. 메트릭 수집 지연 (15초 주기)

VPA 추천이 적용되지 않음

흔한 원인:

  1. updateMode: Off 설정
  2. minAllowed/maxAllowed 범위 밖
  3. PDB(PodDisruptionBudget)로 인한 재생성 차단

Karpenter Node가 프로비저닝되지 않음

흔한 원인:

  1. requirements 충족 인스턴스 타입 없음
  2. 서브넷/보안 그룹 태그 누락
  3. IAM 권한 부족
